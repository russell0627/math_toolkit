This document provides a comprehensive, deep-dive specification for the **Algebraic Auditor (ALG-01) / Algebra Solver** module contained within `math_tools`. ## 2. Core Data Models & State Architecture

### 2.1 `EquationPair` Model
Represents a single equation or inequality statement in the system.
- `left` (`String`): Left-hand side expression (LHS), e.g., `"2x + 5"`.
- `right` (`String`): Right-hand side expression (RHS), e.g., `"15"`.
- `relation` (`String`): Relation operator (`"="`, `"<"`, `">"`, `"<="`, `">="`).

### 2.2 `OperationSuggestion` Struct
Represents a context-aware recommendation generated by the audit engine.
- `op` (`String`): Operation symbol (`"+"`, `"-"`, `="*"`, `"/"`, `"FACTOR"`, `"ISOLATE"`, `"CROSS"`).
- `value` (`String`): Target term or variable value.
- `justification` (`String`): Bureaucratic reasoning text (e.g., `"NEUTRALIZE LEFT CONSTANT"`).
- `display` (`String` getter): Formatted display string, e.g., `"+ 5"`.

### 2.3 `AlgebraState` Model
- `equations` (`List<EquationPair>`): Active list of equation pairs in the workspace.
- `selectedIndex` (`int`): Index of currently selected equation being manipulated.
- `multiSelectIndices` (`List<int>`): Indices of equations selected for multi-equation system solving ($2 \times 2$ systems).
- `history` (`List<AlgebraState>`): Full undo/redo audit stack capturing previous states.
- `suggestions` (`List<OperationSuggestion>`): Real-time list of tactical recommendation chips.
- `resolvedVariables` (`Map<String, String>`): Map of variables already solved across the system (e.g., `{"y": "4"}`).
- `previewEquation` (`EquationPair?`): Hover preview equation state used for shadow auditing.
- `error` (`String?`): Error message banner string (e.g., `"INVALID STATEMENT: NO RELATION DETECTED"`).
- `lastOp` (`String?`): Log string of last performed action (e.g., `"PROTOCOL-DRAG: RELOCATED +5"`).
- `showAuditStamp` (`bool`): Flag controlling display of the tactile `"AUDIT VERIFIED"` stamp.

## 3. Algebraic Manipulation Operations

The tool supports both manual interactive manipulations and automated algebraic protocols:

### 3.1 Protocol Drag (`moveTerm`)
- **Action**: Interactively relocation of a specific term from LHS to RHS or vice versa.
- **Algorithm**:
  1. Regex parses operator (`+` or `-`) and term payload (e.g., `"+ 5x"`).
  2. Computes inverse operation (e.g., `- 5x`).
  3. Applies inverse operation to both sides of the selected equation (`applyOperation`).
  4. Records operation log: `"PROTOCOL-DRAG: RELOCATED [term]"`.

### 3.2 Protocol Merge & Minimize (`handleTermTap` / `simplifySide`)
- **Action**: Simplifies a single side (LHS or RHS) independently.
- **Algorithm**:
  - `_iterativeSimplify(raw)` runs up to 5 iterations of expression parsing via `math_expressions` `simplify()` method combined with polynomial reduction (`_resolveExpression`).

### 3.3 Symmetry Protocol (`swapSides`)
- **Action**: Swaps LHS and RHS of the active equation pair.
- **Operator Inversion Logic**:
  - `=` remains `=`
  - `<` flips to `>` (and `>` flips to `<`)
  - `<=` flips to `>=` (and `>=` flips to `<=`)

### 3.4 Centralization Protocol (`centralize`)
- **Action**: Moves all variable-containing terms to LHS and all constant terms to RHS.
- **Algorithm**:
  1. Expands and normalizes both sides.
  2. Splits expressions into separate additive terms (`_getSeparatedTerms`).
  3. Moves constant terms from LHS to RHS with sign inversion (`_invertTerm`).
  4. Moves variable terms from RHS to LHS with sign inversion.
  5. Runs resolution pass (`_resolveExpression`) on both sides.

### 3.5 Symbolic Expansion (`symbolicExpand`)
- **Action**: Distributes parenthetical terms and expands multiplied polynomial expressions into expanded form.

### 3.6 Cross-Multiplication Protocol (`crossMultiply`)
- **Action**: Resolves fractional proportions $\frac{A}{B} = \frac{C}{D}$.
- **Algorithm**:
  1. Extracts numerators and denominators from LHS and RHS using `_extractFractionParts`.
  2. Formulates cross-multiplied equation: $(A \cdot D) = (C \cdot B)$.
  3. Resolves and simplifies expressions on both sides.

### 3.7 Polynomial Factoring (`factor` / `_factorExpression`)
- **Action**: Decomposes single-variable quadratic polynomials $ax^2 + bx + c$ into factored form $a(x - r_1)(x - r_2)$.
- **Algorithm**:
  1. Samples expression at $x = 0, 1, 2$ to evaluate $f(0), f(1), f(2)$.
  2. Solves for quadratic coefficients:
     - $c = f(0)$
     - $a = \frac{(f(2) - f(1)) - (f(1) - f(0))}{2}$
     - $b = f(1) - a - c$
  3. Validates $a \neq 0$ and discriminant $D = b^2 - 4ac \geq 0$.
  4. Computes real roots $r_1 = \frac{-b + \sqrt{D}}{2a}$ and $r_2 = \frac{-b - \sqrt{D}}{2a}$.
  5. Formats output as $a(x - r_1)(x - r_2)$.

### 3.8 Secret Code System & Unsanctioned System Override
- **Secret Passcode**: Entering the passcode string `"0000"` into the operation parameter value input (`_opValueController`) acts as a hidden administrative override.
- **Trigger Logic**: `_applyOp()` checks `if (val == "0000")`, intercepts normal operation execution, and calls `toggleAutoSolve()`.
- **System State Change**: Toggles `isAutoSolveEnabled` in `SettingsCtrl` and records audit log: `"UNSANCTIONED SOLVE UNIT COMMISSIONED"`.
- **UI Override Element**: Reveals the red high-clearance override button [`_UnsanctionedSolveButton`](file:///c:/C/Users/Owner/IdeaProjects/math_tools/lib/features/algebra/presentation/widgets/algebra_auditorium.dart#L1350) labeled `"ACCESS UNSANCTIONED AUTO-SOLVE"`, granting one-click auto-resolution for complex equations.

## 4. Mathematical Solvers & Analytical Engines

### 4.1 Single Variable Analytical Solver (`solve`)
Solves single-variable equations of linear or quadratic form, or isolates variables in multi-variable equations.

#### Linear Case ($ax + b = 0$)
- Samples $f(0)$ and $f(1)$ to compute slope $m = f(1) - f(0)$ and constant $c = f(0)$.
- Solution: $x = -\frac{c}{m}$.
- Flips inequality relations if dividing by a negative slope ($m < 0$).

#### Quadratic Case ($ax^2 + bx + c = 0$)
- Samples $f(0), f(1), f(2), f(3)$ to evaluate acceleration $a = \frac{\text{accel}_1}{2}$ and coefficient $b$.
- Computes Discriminant $D = b^2 - 4ac$:
  - **$D > 0$ (Two Real Roots)**: Computes $r_1, r_2 = \frac{-b \pm \sqrt{D}}{2a}$. Supports exact radical formatting if `isRadicalMode` is enabled.
  - **$D = 0$ (Single Repeated Root)**: Computes $r = -\frac{b}{2a}$.
  - **$D < 0$ (Complex Roots)**: Triggers error toast `"NO REAL ROOTS (NON-BUREAUCRATIC)"`.

#### Inequality Solution Sets
- For quadratic inequalities ($ax^2 + bx + c \text{ [rel]} 0$), evaluates test points inside and outside the root intervals:
  - **Interval Output**: $r_1 < x < r_2$ (or $r_1 \le x \le r_2$).
  - **Disjoint Output**: $x < r_1 \text{ OR } x > r_2$.
  - **All Real Numbers**: Output `"SYSTEM STABILIZED: ALL REAL NUMBERS VALID"`.
  - **No Solution**: Output `"NODE COLLAPSE: NO SOLUTION DETECTED"`.

### 4.2 Systems of Linear Equations Solver (`solveSystem`)
Solves $2 \times 2$ systems of linear equations in 2 variables using **Cramer's Rule**.
1. Requires exact multi-selection of 2 equations (`multiSelectIndices.length == 2`).
2. Identifies the 2 unique variables ($v_1, v_2$) across both equations.
3. Converts each equation to standard form $a_i v_1 + b_i v_2 = C_i$ via coefficient sampling at $(0,0), (1,0), (0,1)$.
4. Computes Determinant:
   $$\text{det} = a_1 b_2 - a_2 b_1$$
5. If $|\text{det}| < 10^{-10}$, returns error `"SYSTEM IS SINGULAR OR LINEARLY DEPENDENT"`.
6. Otherwise computes unique solutions:
   $$v_1 = \frac{C_1 b_2 - C_2 b_1}{\text{det}}, \quad v_2 = \frac{a_1 C_2 - a_2 C_1}{\text{det}}$$

### 4.3 Candidate Solution Verification Protocol (`verifyCandidates`)
Allows users to verify candidate numerical values or coordinate pairs (e.g. `x=3, y=5; x=1, y=2` or `(3, 5)`).
1. Parses binding maps from input string.
2. Evaluates the difference expression $\text{LHS} - \text{RHS}$ for each candidate set.
3. Checks whether the difference satisfies the relation ($=, <, >, \le, \ge$).
4. Displays formatted valid solution sets or errors if no candidates satisfy the system.

### 4.4 Multi-Variable Substitution & Resolution
- Maintains `resolvedVariables` map across equations.
- Automatically substitutes known variable values (e.g., if Equation 1 yields $y = 4$, substitute $4$ for $y$ in Equation 2).

## 5. Tactical Recommendations Engine (`_updateSuggestions`)

The suggestion engine inspects the current equation state and generates a horizontal list of recommended next operations (`SuggestionChips`):

1. **Proportional Fraction Detection**: Recommends `CROSS MULTIPLY` if division operators are present.
2. **Multi-Variable Isolation**: Recommends `ISOLATE [var]` for each present variable.
3. **Left Constant Neutralization**: Recommends subtracting/adding left constant value.
4. **Right Constant Neutralization**: Recommends subtracting/adding right constant value.
5. **Variable Centralization**: Recommends moving RHS variable terms to LHS.
6. **Coefficient Isolation**: Recommends dividing by leading coefficient if variable is already centralized.
7. **Factoring**: Recommends `FACTOR` if LHS polynomial can be decomposed.

## 6. UI Components & Visual Instrumentation

### 6.1 `AlgebraAuditorium` Screen
- **System HUD**: Displays active equation pair, equation status, last operation log, auto-solve toggle, and multi-select checkboxes.
- **Equation Input Fields**: Double text-field input for LHS and RHS with relation selector dropdown (`=`, `<`, `>`, `<=`, `>=`).
- **Tactile Keypad Bar**: Buttons for operators (`+`, `-`, `*`, `/`, `^`, `SQRT`, `CROSS`, `FACTOR`, `ISOLATE`, `CENTRAL`, `SOLVE`, `VERIFY`).
- **Audit Verification Stamp**: `BureauStamp` displaying `"AUDIT VERIFIED"` upon successful resolution.

### 6.2 Visual Indicators
- **Bureau Balance Scale (`BureauBalanceScale`)**: Real-time animated balance beam displaying visual tilt when LHS and RHS values diverge.
- **Bureau Complexity Gauge (`BureauComplexityGauge`)**: Meter gauge measuring equation complexity based on variable count, term length, and exponent order.

### 6.3 Suggestion Chips & Shadow Preview (`SuggestionChips`)
- Renders glowing blue recommendation chips.
- **Hover Preview**: Hovering over a chip temporarily renders the predicted outcome in the equation preview area (`setPreview`).
